### 用户报的 bug：停用后刷新居然有数据

**根因是进程跑了旧代码，不是逻辑错。** 控制面进程 9:44 启动，`app.py` 15:19 才改——
磁盘上的 409 守卫根本没在运行。旧代码里停用的 link 被问状态时会去 probe，
`ModbusTcpClient` 发现 socket 关了就自动重连，所以点刷新**真的建了一条新连接**。

用户的判断是对的（"如果每次点击都创建一个 client 那就是有大问题"）。已确认
实际情况是：**每个实例只有一个 client，缓存在 `app.state.link_supervisors` 里复用**，
不存在按请求创建。停用后对端新增连接数实测为 0。

### 教训：改了 pyproject 或 app.py 后，`uv run` 才会重新解析/加载

`.venv/Scripts/python -m pytest` 用的是已经 import 好的旧模块，`uv run` 才是新的。
之前 poly-modbus 包名那次也是同一个陷阱（已记在 2026-10-22）。

### 本轮我改的

**后端**
- 删掉 `update_server` 里与 `else` 分支完全等价的死分支
- `_forget` 删除 link 时 `app.state.link_supervisors.pop(row.id)`——否则每建过
  一个 link 就漏一个 supervisor 对象（client + 事件队列）
- 新增测试 `test_a_disabled_link_opens_no_new_connection`：在对端 `_serve` 外面
  包一层计数，证明停用后一次刷新都不会新建 TCP 连接。已验证拆掉 enabled 守卫
  后该测试会失败（400≠409）。

**前端**
- `SitesPage` 端口兜底不再写死 25011，改用 `window.location.origin`
  （80/443 时 `location.port` 是空串，写死数字会打印一个不存在的地址）
- 不可用协议的卡片从 `<Link>` 改成 `<div aria-disabled>`——之前点了会跳到
  空列表，像 bug
- `DataAreaView` 停用时渲染整幅阻塞面板（带「启用」按钮）而不是一行小字；
  停用后**完全不渲染数据网格**（空的零格会被人读成"设备说全是 0"）
- API 因停用拒绝时：弹 toast + `loadServer(id, true)` 重新拉实例，让页面自己追上现实
- 踩了一个自己的坑：CSS 里写了 `var(--text-dim)`，这个 token 不存在（只有
  `--muted` / `--dim`）。已改用 `--muted`
