## 同机多实例：撤掉「每协议一个」，把隔离做实（379ab6d）

用户直接质疑了我上一轮刚加的那条规则：「我创建了同一台创建2个modbus,2个opc ua
这种，会不会起冲突」。答案是**不冲突，规则是我加错了**——多实例本来就不共享任何
东西（独立子进程/内存/数据面、独立 `configs/<id>.json` + `logs/<id>.log`、独立
临时控制端口；远程侧还有 `instance_dir(id)` 与按 config 路径匹配的 pid 文件）。
`_protocol_conflict` 及文档里那条 bullet 全删。**端口是唯一硬约束**。

### 三处真会悄悄破坏隔离的代码（读代码发现的，不是报错逼出来的）

1. `Supervisor.check_bind` 用裸 `SO_REUSEADDR` 探测。
2. `ModbusTcpAdapter.start` 真监听也用裸 `SO_REUSEADDR`。
3. `_local_bind_error` 用裸 `bind` 探测（POSIX 下比真监听严、Windows 下比独占松）。

关键认知：**POSIX 的 SO_REUSEADDR 只回收 TIME_WAIT，Windows 的同名选项允许
任何人抢占任何人的端口**。后果是两个实例都「启动成功」，只有一个收到请求——
最难查的那类 bug，因为每一层单独看都健康。Windows 对应语义是
`SO_EXCLUSIVEADDRUSE`。三处统一收敛到 `packages/plc-core/poly_core/net.py`：
`bind_for_listening()` + `can_bind()`，**预检和真监听共用同一个函数**，
「查时说空闲」与「绑时能绑上」才不会打架（为此 poly-agent 加了 poly-core 依赖）。

### 端口检测前置

- 新端点 `GET /api/sites/{id}/port-check?port=&bind_ip=&exclude=`，**只回答不落库**，
  被占就 200 + `available:false` + 原因（占用是选端口的正常一步，不是错误状态）。
- 前端端口输入框**失焦即查**，黄字=占用 / 绿字=可用，改端口或换监听地址清空结论。
  **不用它卡提交**——答案会过期，服务端保存时才是判决。
- `exclude` 只放宽数据库那一半；运行中的实例自己占着 socket，live 探测照样报占用。
  这不是 bug，正是保存路径「只在端口真变了才检查」的原因（我一开始还把它当 bug 写进了
  验证脚本，被真实行为纠正）。

### 跨平台边界（2026-10-26 定）

控制面 Windows / Linux / macOS 都能跑；**远程 site 只支持 Linux**——靠
`uname` / `ss` / `pkill` / `nohup` 管进程。`ssh.probe_target` 先跑 `_posix_target()`：
无 `uname`（cmd/PowerShell 当 SSH shell）或 Git-Bash 的 `MINGW64_NT-*` 一律
`ok=False` + 明确原因，**掐断在第一个命令**而不是跑完一串注定失败的探测——

## Windows 一律本机运行，远程只做 Linux（cb94206）

用户在我做完「跨平台支持」之后给了明确边界：「windows的话就不要做什么远程连接了…
windows的话用户自己直接执行就行，而不是通过所谓远程部署上去」。所以 Windows 不是
「暂不支持」，是**排除**。落地重点不是加限制，而是**把拒绝写成规则而不是故障**：

- `ssh._platform_verdict()` 在探测第一步返回 `(os, 拒绝原因)`，三分支：Linux 放行 /
  Windows（无 `uname`，或 `MINGW64_NT-*`，`cmd /c ver` 确认）/ 其他 POSIX（Darwin 等）。
  后两者立刻 return，不再跑后续命令。
- **拒绝时保留 `os`**，前端据此换语气：sites 列表 chip 由红「连接失败」改成中性
  「仅本机运行」，创建弹窗由红 `error-box` 改成琥珀 `notice`。理由：红色会让用户去查
  SSH 凭据，而这里根本没有 SSH 问题。这是「状态要对，语气也要对」的一个小例子。
- `decide_carrier` 对 Windows 给「Windows 机器只能本机运行」+「在那台上直接运行控制面」，
  而不是「这台机器不能部署实例」。
- 顺手清了文档里的历史残留：AGENTS 约束 2–5 还写着 WS agent / `config_version` 收敛 /
  last-known-good，这套 agent 从未实现（现行是 SSH 按需推送 + `enabled` 期望状态）；
  architecture §4 把废弃方案写成「目标形态」，等于留了复活口子，已标注为废弃。
- 也修了个我自己的错误表述：OPC UA 的 link 不是「缺客户端库」——`asyncua` 2.x 自带
  `Client`，障碍是纯异步 API 对同步的 `LinkClient`，要一条常驻事件循环桥接。

## Modbus 数据区到底有多少个地址（9d7308a）

用户问"默认创建的保持寄存器是多少个？还是没有限制？肯定不太对吧"。答案是**没限制**：
四个区各按完整 16 位地址空间（0–65535，65536 点）分配，初值全 0，任何地址可读写，
内存实测 **2.00 MB/实例**（4 个 65536 的 list）。页面看到的"50"只是视图窗口
（`PAGE_SIZE=50`，长度最多 1000），协议单帧另有硬限：寄存器 125 / 位 2000。

这么设计是刻意的：现场扫描工具（OpenModScan 等）会扫固定范围，窗口一小就回非法地址，
容易被当成"模拟器坏了"。但用户的直觉也对——真设备只有几百上千个地址，越界要回异常码
02，而"客户端拿到 02 怎么处理"恰恰是最需要测的一条分支。所以做成可选：

- `ServerOptions.register_count`（1–65536，默认 null = 整段）。四区共用，从 0 起算。
- 实现取巧但干净：**分配长度就是上限**。`poly_modbus.server.area_size()` 决定四个数组
  多大，于是既有的 `address + count > len(area)` 检查（单读/多读/单写/多写、位/寄存器）
  自动回 ILLEGAL_ADDRESS，协议处理一行没改。配小了内存也真降。
- `/area` 响应带 `limit`，GET/POST 按它拦；link 恒为 65536（对端映射由对端说了算）。
- UI 三处：创建弹窗（仅 Modbus）一个「有效寄存器数」；数据区视图头部「有效 0–99」+
  请求前拦截；实例页「每区 N 点」旁「改」可就地改（`PATCH options` → 重启）。
  注意 `api.updateServer` 之前根本没暴露 `options`，这轮才补上。

测试 57 全绿（+适配器边界 2 项、+HTTP 1 项）；真机验证 9 项：配 100 → 99 可读/100 回
02；PATCH 改 10 → 重启后 9 可读/10 回 02；留空改回整段 → 40000 又能读。
