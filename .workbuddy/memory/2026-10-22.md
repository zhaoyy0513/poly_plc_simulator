## 远程 site + server/client 双身份：设计定型

用户诉求：site 应该绑定一台真实服务器（填访问信息），创建实例 = 部署到那台机器；同时要能「连别人的 server」（如 18 环境 502），页面逻辑与自建实例一致；实例要标清 server / client 身份。用户对「统一平台 vs 每服务器独立部署」摇摆不定，要求我给方案。

用 brainstorming skill 逐个问题确认，最终决策（**已写进 docs/plans/2026-10-22-remote-site-server-client-design.md**）：

1. 部署形态：**统一平台 + SSH 推送**，目标机不常驻 agent
2. 连接形态：**平台直连**（不做本地端口代理），数据源抽象预留代理能力
3. site 语义：**site = 一台机器**；`host` 为空 = 本机（兼容现有 local site，免迁移）
4. 使用范围：单人多环境，**不做登录/权限**
5. SSH 认证：**账号密码**，端口可配，UI/API 不明文，DB 用本地密钥加密
6. link 协议：先 **Modbus + OPC UA**（S7 client 在 Windows 需 snap7.dll，后置）
7. 部署载体：**native 推脚本**（docker 只留 runtime 字段口子）——我拍板，理由是简单好清理
8. 远程进程管理：**纯 SSH 按需查询**，SSH 连接按 site 复用；远程 runtime 控制端口仍只绑目标机 127.0.0.1，平台走 SSH channel 打过去

数据模型：site 加 host/ssh_port/ssh_user/ssh_secret/deploy_dir/python_bin/last_probe；server 加 `kind`（sim|link）+ target_host/target_port/target_options。**注意没有 Alembic，`create_all()` 不会给旧表加列，必须手写 `PRAGMA table_info` + `ALTER TABLE ADD COLUMN` 的幂等迁移。**

核心抽象：`DataSource` 接口（health/read_area/write_area/read_snapshot/write_named/logs），四个实现：LocalRuntime / SshRuntime / ModbusClient / OpcUaClient。现有 `GET|POST /api/servers/{id}/area` 可直接复用，不用新增数据面端点。

实施分 P1–P5（见文档第 9 节），测试策略：SSH 层用 FakeRunner 断言命令序列；link 数据源用「本地起 sim 实例当别人的 server」做真实端到端。
